Code Interpreter (internally **`codeapi`**: the prefix on its environment
variables, container images, and Helm chart) is a self-hostable service that
executes untrusted code safely. It is what sits behind LibreChat's code
interpreter feature: a model writes a program, this service runs it in a
sandbox, and the output and any files it produced come back.

It is built for the case where the code is genuinely untrusted: written by a
language model, on behalf of a user you may not know, doing whatever it likes.

## What it does

- **Runs code in a real sandbox.** Python, Node.js, Bun (JS/TS), Bash, and Java,
  each in a fresh isolated workspace with CPU, memory, PID, and wall-clock
  limits enforced by the kernel.
- **Handles files.** Callers upload files, code reads them, code writes new ones,
  and the results come back as downloadable artifacts: all through
  S3-compatible object storage, scoped per user.
- **Supports tool calling.** Sandboxed programs can pause, call back into
  caller-provided tools, and resume with the results.
- **Scales horizontally.** API, workers, file server, and gateway are separate
  components communicating over Redis and object storage, so each scales on its
  own.

## The isolation model, briefly

There are two modes, and the difference between them matters more than anything
else in this documentation.

<Callout type="warn" title="Read this before deploying">
**MicroVM mode** (`KVM_ENABLED=true`, the default) runs the sandbox inside a
libkrun microVM with **its own guest kernel**, with NsJail inside the guest. A
kernel exploit in sandboxed code hits the guest kernel, not yours.

**NsJail-only mode** (`KVM_ENABLED=false`) shares the host kernel. It is
appropriate for local development and trusted code. It is **not** appropriate
for executing untrusted code from people you don't trust.
</Callout>

In its full hardened configuration (microVM mode, seccomp filtering, the
egress gateway in front of all sandbox-originated traffic, network policies
applied, signed execution manifests, and `CODEAPI_HARDENED_SANDBOX_MODE` left
on) the service is designed with defense in depth and is reasonably secure.

No software is 100% secure. Sandbox escapes, kernel vulnerabilities, and
misconfiguration are real risks for any code-execution system. Keep the
hardening defaults on, run the stack on isolated infrastructure with least
privilege, keep hosts patched, and deploy responsibly. If you believe you have
found a vulnerability, please report it privately rather than opening a public
issue.
